# Deployment Checklist

## Pre-Deployment

- [ ] All code changes committed
- [ ] `.env` file NOT committed (check `.gitignore`)
- [ ] `data/question_ids_enriched.csv` exists and has data
- [ ] `requirements.txt` is up to date
- [ ] Database migrations are created
- [ ] Local testing completed

## GitHub Setup

```bash
# Initialize git (if not already done)
git init

# Add all files
git add .

# Commit
git commit -m "Setup for Render deployment with question data"

# Add remote (replace with your repo URL)
git remote add origin https://github.com/yourusername/stress-dost-web.git

# Push to GitHub
git push -u origin main
```

## Render Setup

### 1. Create Web Service

1. Go to https://dashboard.render.com/
2. Click "New +" → "Web Service"
3. Connect GitHub repository
4. Render will detect `render.yaml` automatically

### 2. Configure Environment Variables

Add these in Render Dashboard → Environment:

**Required Secrets:**
```
OPENAI_API_KEY=sk-...your-key...
ACADZA_COURSE=JEE
ACADZA_AUTH=Bearer ...your-token...
ACADZA_API_KEY=...your-key...
```

**Optional (already in render.yaml):**
- PORT (auto-generated by Render)
- FLASK_ENV=production
- SOCKETIO_CORS_ALLOWED_ORIGINS=*
- MIN_QUESTIONS=7
- MAX_QUESTIONS=7
- MAX_DOMAIN_QUESTIONS=7

### 3. Deploy

- Click "Create Web Service"
- Wait for build (~5-10 minutes)
- Check logs for errors

### 4. Verify Deployment

- [ ] App URL loads successfully
- [ ] Login page appears
- [ ] Can create user profile
- [ ] Subject selection works
- [ ] Questions load correctly
- [ ] Triggers activate properly
- [ ] Socket.IO connects (check browser console)

## Post-Deployment

### Test Checklist

1. **User Flow**:
   - [ ] Register new user
   - [ ] Select subject and chapter
   - [ ] Start test
   - [ ] Answer questions
   - [ ] Complete test
   - [ ] View results

2. **Triggers**:
   - [ ] Bouncing question trigger works
   - [ ] Spotlight trigger works
   - [ ] Other triggers activate

3. **Data**:
   - [ ] Questions load from CSV
   - [ ] User sessions persist
   - [ ] Trigger randomization works for returning users

### Monitoring

Check Render logs for:
- Application startup
- Database connections
- API calls
- Socket.IO connections
- Any errors or warnings

### Common Issues

**Build Fails:**
- Check Python version in `runtime.txt`
- Verify all dependencies in `requirements.txt`
- Check Render build logs

**App Crashes:**
- Verify environment variables are set
- Check database migrations ran
- Review application logs

**Questions Not Loading:**
- Verify `data/question_ids_enriched.csv` is in repository
- Check file path in environment variables
- Review API logs

**Socket.IO Issues:**
- Check CORS settings
- Verify eventlet is installed
- Check browser console for connection errors

## Rollback Plan

If deployment fails:

1. **Revert to previous commit:**
```bash
git revert HEAD
git push origin main
```

2. **Render will auto-deploy the reverted version**

3. **Or manually trigger previous deployment in Render dashboard**

## Maintenance

### Update Dependencies

```bash
pip freeze > requirements.txt
git add requirements.txt
git commit -m "Update dependencies"
git push
```

### Database Migrations

```bash
# Create migration
python -m flask db migrate -m "Description"

# Commit and push
git add migrations/
git commit -m "Add database migration"
git push
```

### Update Question Data

```bash
# Update CSV files
git add data/*.csv
git commit -m "Update question data"
git push
```
